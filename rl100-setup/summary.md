# 1. 2D 与 3D 策略的速度对比

## 测试条件

- **配置与口径**：单张 RTX 4090 D、FP32、batch 128、3 帧观测，预热 5 步后测量 20 步取中位数，开启 `CUDA_LAUNCH_BLOCKING=1`。计时包含数据传入 GPU、前向、反向、优化器和 EMA，不含数据加载等待、仿真、评估及存盘。分段比例来自详细计时。

## 核心结果

| 方法与动作网络 | 2D 每步耗时 | 3D 每步耗时 | 2D / 3D 耗时比 | 2D / 3D 峰值分配显存 | 观测编码前向与反向占额外耗时 |
|---|---:|---:|---:|---:|---:|
| Diffusion + SkipNet，单动作 | 199.63 ms | 31.83 ms | **6.27 倍** | 9,416 / 2,097 MiB | 97.7% |
| Flow + SkipNet，单动作 | 200.66 ms | 35.22 ms | **5.70 倍** | 9,416 / 2,097 MiB | 97.0% |
| Diffusion + U-Net，16 动作块 | 236.82 ms | 72.19 ms | **3.28 倍** | 10,826 / 3,428 MiB | 97.5% |
| Flow + U-Net，16 动作块 | 245.22 ms | 74.06 ms | **3.31 倍** | 10,826 / 3,428 MiB | 96.3% |

- **数据来源**：[Diffusion 单动作](reports/diffusion-speed.json)、[Flow 单动作](reports/flow-speed.json)、[Diffusion 动作块](reports/diffusion-chunk-speed.json)、[Flow 动作块](reports/flow-chunk-speed.json)；本次沿用已有报告，未重跑。

## 结论与采用方案

- **观测编码**：2D 更慢，主要慢在观测编码器。 2D 使用 ResNet18 处理放大到 `224×224×3` 的 RGB 图像，编码器约 **1,227 万参数**；3D 使用较轻的 DP3VIB 点云编码器，输入为 `512×3`，约 **223 万参数**。512 个点来自深度图转点云后进行工作空间裁剪和最远点采样。实测 2D 编码前向约 62–63 ms、反向约 123–125 ms；3D 分别约 9 ms、15–16 ms，解释了约 **96%–98% 的额外耗时**。
- **动作网络**：U-Net 动作块的耗时比降至约 3.3 倍，是因为两者共同的动作网络计算更重。 SkipNet 动作网络前向加反向约 2–3 ms，U-Net 动作块约 28–29 ms。2D 整步仍比 3D 多约 160–170 ms，但 3D 整步本身从约 32–35 ms 增至 72–74 ms，因此相对倍数变小。这里同时改变了网络结构和动作长度，不能把差异全部归因于 U-Net。
- **方法比较**：同一网络与动作配置下，Flow 和 Diffusion 的 BC 耗时接近。 本次主要差距来自观测编码和动作网络的计算；小幅时间差不足以判断哪种方法本身更快。

# 2. SkipNet、U-Net 与动作步数的速度对比

## 测试条件

- **配置与口径**：单张 RTX 4090 D、FP32、batch 128、3 帧观测、统一 Mish 激活；预热 4 步，重复 3 轮、每轮 6 步取中位数，计时范围同上。当前 U-Net 不支持此配置下的单动作输入，未列入比较。数据见 [测速表](reports/network-chunk-speed.csv)。

## 核心结果

- **单位**：毫秒／BC 更新。

| 配置 | SkipNet：1 动作 | SkipNet：4 动作 | SkipNet：16 动作 | U-Net：4 动作 | U-Net：16 动作 |
|---|---:|---:|---:|---:|---:|
| 3D Diffusion | 32.65 | 37.08 | 34.35 | 68.20 | 73.49 |
| 3D Flow | 35.92 | 35.10 | 33.71 | 67.06 | 72.69 |
| 2D Diffusion | 196.87 | 198.55 | 198.30 | 231.18 | 241.63 |
| 2D Flow | 198.75 | 200.44 | 210.07 | 233.15 | 249.63 |

- **数据来源**：[测速表](reports/network-chunk-speed.csv)、[完整报告](reports/network-chunk-speed.json)；本次未重跑。

## 结论与采用方案

- **网络与动作长度**：主要差距来自网络结构，动作步数的影响较小。 同为 16 动作，U-Net 整步耗时是 SkipNet 的 2.14–2.16 倍（3D）／1.19–1.22 倍（2D）；单独测动作网络更新约慢 10–11 倍，其参数约 7,076–8,831 万，SkipNet 约 191–223 万。SkipNet 从 1 动作增至 16 动作耗时变化约 ±6%；U-Net 从 4 动作增至 16 动作仅增加约 5%–8%，因此不能按动作数估算训练耗时。

# 3. 3D 单动作正式训练结果

## 测试条件

- **配置与口径**：Adroit Door medium，seed 100、tag 0112、DP3VIB 点云编码器与 SkipNet；Diffusion BC 600 epoch，Flow BC 800 epoch。在线各有 51 个评估点（含初始点），历史导出记录的训练终点为 100 万环境步；两条在线 W&B 记录均 exit 0。以下为末次仿真评估，不能视为多种子统计。

## 核心结果

| 方法 | 所选离线配置评估成功率 | 最终在线主策略 | 最终在线 EMA | 最终 CM |
|---|---:|---:|---:|---:|
| 3D Diffusion | 76.67% | 100% | 100% | 100% |
| 3D Flow 单步 | 80.00% | 0% | 0% | 0% |

- **数据来源**：[曲线索引](presentations/curves/figure-manifest.json)、[本地原始导出（Git 忽略）](presentations/curves/training-histories.json)；运行与分析见[实验总结](实验总结.md)。离线值分别对应所选配置第 3,000／4,000 次更新，不代表最终在线初始化的评估值。

## 结论与采用方案

- **训练结果**：本次 Diffusion 末次仿真评估成功，Flow 单步在线退化至 0%；已有单步 Flow 在线缺陷尚未通过修复后重训对照确认其因果影响，不能据此概括两种方法整体优劣，也没有真机效果证据。

# 4. Summary 更新规则

## 通用要求

- 按主题使用连续编号标题（1、2、3……），每个主题固定采用下列三个小标题；规则置于文末，新增主题时顺延编号。
- 让未读源码的人也能复查“测了什么、结果是什么、采用了什么方案”。保留关键条件与证据，不记录讨论过程、排查流水和操作教程。
- 正文统一使用 `- **简短标签**：内容`，指标使用表格；同类信息合并为一条，不拆成零散段落，不用嵌套列表。
- 三部分按内容决定长短，不凑条目、不重复指标；仅突出关键结果，历史改动写入测试进展，完整命令和逐次记录通过链接引用。

## 测试条件

- 通常合并为一条“配置与口径”；条件较多时分为“测试配置”和“计时口径”两条。只保留影响比较的硬件、模型/权重、关键参数、样本数和统计范围。

## 核心结果

- 指标与对照优先用表格，注明单位；误差、内存变化等必要补充紧跟表格，数据来源以单独一条放在本节末尾。
- 核心结果包含多类指标时，按结果类型增加编号三级标题，将统计口径、表格及解释归入对应类别；单一结果可直接列出，数据来源统一放在末尾。
- 区分实测、估算和未通过项，不把不同计时范围或不同配置的结果直接混比。

## 结论与采用方案

- 用一至三条写清结论、最终采用的设置及关键参数；没有方案选择的主题只写一条结论。
- 简要注明影响结论的重要未验证范围，不将合成数据或局部测试写成真机效果，也不将数值近似写成完全一致。
